**MCP-сервер к базе магазина — один промпт от спеки до зелёных гейтов**

Условия задачи: read-only MCP-сервер (stdio) над SQLite-базой магазина;
сдача — живой AI-агент отвечает через него на 8 контрольных вопросов. Три
инструмента: `list_tables`, `describe_table`, `read_query`. Python 3.13,
официальный `mcp` SDK, uv.

Результат: сначала спецификация ~14k токенов (~1240 строк, 82 требования) —
точные JSON-конверты ответов, политика «только SELECT/WITH» плюс
sqlite3-authorizer вторым эшелоном, лимиты 2 с / 200 строк и зашитые ловушки
базы: колонки со страной нет, а все 750 заказов датированы 2026-м — сервер
обязан отдать честные данные, а не повод фантазировать. Дальше
claude-sonnet-5 (Claude Code) получил ровно один промпт,
`go docs/spec/spec-v0.md`: server.py, 71 тест, smoke-клиент, README — все
4 гейта зелёные с первого прогона (0/5 циклов починки). Ревью в чистом
контексте: approve, 2 минорных замечания исправлены отдельным коммитом.

Метрики:
• спека — ~14k токенов; её авторинг + ревью ~231k + 153k (агрегат харнесса)
• промптов на реализацию — 1 (+ ревью сабагентом в чистом контексте)
• first-run — да; багов — 0 блокирующих, 2 минорных (исправлены)
• реализация (claude-sonnet-5): 13,75M in (из них 13,54M — кэш-чтение) /
  97,5k out — харнесс счётчики агенту не отдаёт, снято с транскрипта сессии
• стоимость: flat-rate подписка; оценка по открытым API-ценам ≈ $4,2

Главный вывод: чем точнее конверты и политики в спеке, тем механичнее
реализация — интеллект тратится на этапе проектирования.
