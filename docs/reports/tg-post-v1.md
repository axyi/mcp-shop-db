🛠 mcp-shop-db: read-only MCP-сервер над SQLite

Задача (учебное задание): по спецификации (~1240 строк, 82 требования) поднять stdio MCP-сервер с тремя инструментами (list_tables, describe_table, read_query) над готовой БД shop.db. Требования: позитивная политика чтения (только SELECT/WITH), защита в глубину — read-only URI + PRAGMA query_only + SQLite authorizer, лимиты 2 с / 200 строк / байтовые капы, гейты uv sync → ruff → pytest → smoke-клиент по stdio, бюджет 5 циклов починки.

Результат: реализованы server.py, 71 тест, smoke-клиент, README, config.example.json. Все 4 гейта зелёные с первого прогона (0/5 циклов починки). Код прошёл ревью в чистом контексте (отдельный агент) — вердикт approve, блокирующих багов нет; 2 мелких замечания устранены отдельным коммитом (защита от гонки при исчезновении файла БД между проверкой и открытием соединения; тест на описания таблиц перестал сравнивать константу саму с собой).

Метрики:
- спецификация: ~231k (авторинг) + ~153k (ревью) токенов, агрегат по харнессу, без разбивки in/out
- промптов на реализацию: 1 (go-запуск по спеке)
- first-run: да (0/5 циклов починки гейтов)
- багов: 0 критических, 2 мелких (оба исправлены)
- токены in/out и стоимость реализации: неизвестны — харнесс их не отдаёт
