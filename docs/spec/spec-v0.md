to an AI agent. This document is the complete contract: everything needed to

mandatory. Anything not stated here is out of scope.

```python
# file: skeleton_server.py
"""SDK boundary reference: a minimal MCPServer served over stdio."""

from __future__ import annotations

import json
import logging
import sys

from mcp.server.mcpserver import MCPServer

log = logging.getLogger("skeleton")


def setup_logging() -> None:
    """Send every log record to stderr. stdout carries protocol frames only."""
    handler = logging.StreamHandler(sys.stderr)
    handler.setFormatter(logging.Formatter("%(levelname)s %(name)s: %(message)s"))
    log.handlers[:] = [handler]
    log.setLevel(logging.INFO)
    log.propagate = False


mcp = MCPServer(
    name="skeleton",
    version="0.1.0",
    instructions="Skeleton server that pins the SDK API surface.",
)


@mcp.tool(structured_output=False)
def echo(text: str) -> str:
    """Return the supplied text inside a JSON envelope."""
    return json.dumps({"ok": True, "text": text}, ensure_ascii=False, separators=(",", ":"))


def main() -> None:
    setup_logging()
    log.info("skeleton server starting")
    mcp.run(transport="stdio")


if __name__ == "__main__":
    main()
```

```python
# file: skeleton_client.py
"""SDK boundary reference: official stdio client — handshake, list, call, clean close."""

from __future__ import annotations

import asyncio
import json
import os
import sys
import tempfile
from pathlib import Path

from mcp import Client, StdioServerParameters
from mcp.client.stdio import stdio_client

HERE = Path(__file__).resolve().parent


def tool_payload(result) -> dict:
    """Decode the JSON envelope carried by the first text content block."""
    assert result.content, "tool returned no content blocks"
    block = result.content[0]
    assert block.type == "text", f"unexpected content block type: {block.type}"
    return json.loads(block.text)


async def run(mode: str) -> None:
    params = StdioServerParameters(
        command=sys.executable,
        args=[str(HERE / "skeleton_server.py")],
        env={**os.environ},
        cwd=str(tempfile.gettempdir()),
    )
    with tempfile.TemporaryFile("w+", encoding="utf-8") as errlog:
        async with Client(stdio_client(params, errlog=errlog), mode=mode) as client:
            listed = await client.list_tools()
            names = {tool.name for tool in listed.tools}
            assert names == {"echo"}, f"tools/list mismatch: {names}"
            result = await client.call_tool("echo", {"text": "hello"})
            assert result.is_error is False, result
            assert tool_payload(result) == {"ok": True, "text": "hello"}
        errlog.seek(0)
        server_stderr = errlog.read()
    sys.stderr.write(server_stderr)
    print(f"SKELETON OK (mode={mode})")


async def main() -> None:
    await run("auto")
    await run("legacy")


if __name__ == "__main__":
    asyncio.run(main())
```

- **REQ-17 (MUST)** `skeleton_server.py` and `skeleton_client.py` are reference
  material only. **Do not create them as files in the repository.**
- **REQ-18 (MUST)** Facts pinned by these skeletons, all verified against
  `mcp==2.1.1`:
  - `MCPServer(name=..., version=..., instructions=...)` — all keyword arguments.
  - `@mcp.tool(structured_output=False)` registers a tool. The decorator must be
    *called*; bare `@mcp.tool` raises `TypeError`.
  - The tool name is the function name; the tool description is the function's
    full docstring; the input schema is derived from the type annotations.
  - `mcp.run(transport="stdio")` is synchronous and blocks until the client
    disconnects.
  - `Client(...)` is an async context manager. `Client(server)` where `server` is
    an `MCPServer` connects **in process** (used by tests);
    `Client(stdio_client(params, errlog=...))` spawns a subprocess (used by
    `smoke_stdio.py`).
  - `mode="auto"` (default) negotiates via a `server/discover` probe;
    `mode="legacy"` forces the classic `initialize` handshake. Both are exercised.
  - `await client.list_tools()` → object with `.tools`; each tool has `.name`,
    `.description`, `.input_schema`.
  - `await client.call_tool(name, args)` → object with `.content` (list of
    content blocks; a text block has `.type == "text"` and `.text`) and
    `.is_error`.
  - Leaving the `async with Client(...)` block is the clean shutdown; there is no
    separate `close()` call.

### 3.7 Connections

- **REQ-34 (MUST)** Exactly one helper opens connections. Its signature is
  `open_connection(*, restricted: bool) -> sqlite3.Connection`. Every tool call
  opens its own connection and closes it in a `finally:` block. No connection,
  cursor or deadline is shared between calls or stored at module level.
- **REQ-35 (MUST)** The helper performs these steps in this order:
  1. raise `FileNotFoundError` if the resolved database path is not a regular
     file;
  2. build the URI as
     `"file:" + urllib.parse.quote(str(path), safe="/") + "?mode=ro"` — this makes
     paths containing spaces, `?`, `#` or `&` work;
  3. `sqlite3.connect(uri, uri=True, timeout=5.0, isolation_level=None)`;
  4. `conn.execute("PRAGMA query_only=ON")`;
  5. install the progress handler of REQ-37;
  6. **only if `restricted` is true**, `conn.set_authorizer(...)` with the
     callback of REQ-39.
- **REQ-36 (MUST)** `read_query` uses `restricted=True`. `list_tables` and
  `describe_table` use `restricted=False`; they run only the fixed internal
  queries listed in section 3.9 and never interpolate user input into SQL text
  other than a `sqlite_master`-validated table name quoted per REQ-45.
- **REQ-37 (MUST)** Query budget: before returning the connection compute
  `deadline = time.monotonic() + 2.0` and install
  `conn.set_progress_handler(lambda: 1 if time.monotonic() > deadline else 0, 1000)`.
  Because the connection is per-invocation the deadline resets automatically on
  every call. An over-budget query raises `sqlite3.OperationalError` whose message
  contains `interrupted`.

### 3.8 SQL policy for `read_query`

- **REQ-38 (MUST)** The accepted input is defined **positively**: exactly one
  read-only statement that begins with `SELECT` or `WITH`. Everything else is
  rejected. The layers are, in order:

  1. **Lexical gate** `check_policy(sql) -> str | None`. Returns a rejection
     message, or `None` when the statement may proceed:
     - strip `--` line comments and `/* */` block comments, then strip
       whitespace; empty result → reject;
     - strip leading `(` and whitespace, take the first whitespace-delimited
       token, lowercase it; if it is not `select` or `with` → reject with a
       message naming the offending keyword. Named consequences, all rejected
       here: `INSERT`, `UPDATE`, `DELETE`, `REPLACE`, `DROP`, `ALTER`, `CREATE`
       (including `TEMP`, `VIEW`, `INDEX`, `TRIGGER`, `VIRTUAL TABLE`),
       `PRAGMA`, `ATTACH`, `DETACH`, `VACUUM`, `ANALYZE`, `REINDEX`, `EXPLAIN`,
       a bare `VALUES` clause, and `BEGIN` / `COMMIT` / `ROLLBACK` /
       `SAVEPOINT` / `RELEASE`;
     - strip one optional trailing `;`; if a `;` remains and
       `sqlite3.complete_statement(body + ";")` is false → reject as multi-statement.

     The lexical gate exists to produce good error messages. It is **not** the
     security boundary.
  2. **Connection mode** — `mode=ro` in the URI plus `PRAGMA query_only=ON`.
  3. **Authorizer** (REQ-39) — the security boundary.
  4. **Single statement** — `conn.execute(sql)` raises
     `sqlite3.ProgrammingError("You can only execute one statement at a time.")`
     for multi-statement input that slipped past the lexical gate.

- **REQ-39 (MUST)** The authorizer is an allowlist. Signature:
  `authorizer(action: int, arg1, arg2, dbname, source) -> int`. Behaviour:

  | condition | decision |
  |---|---|
  | `action == sqlite3.SQLITE_FUNCTION` and `arg2.lower()` in `DENIED_FUNCTIONS` | `sqlite3.SQLITE_DENY` |
  | `action == sqlite3.SQLITE_FUNCTION` otherwise | `sqlite3.SQLITE_OK` |
  | `action` in `ALLOWED_ACTIONS` | `sqlite3.SQLITE_OK` |
  | anything else | `sqlite3.SQLITE_DENY` |

  with exactly:

  ```python
  ALLOWED_ACTIONS = frozenset(
      {
          sqlite3.SQLITE_SELECT,
          sqlite3.SQLITE_READ,
          sqlite3.SQLITE_FUNCTION,
          sqlite3.SQLITE_RECURSIVE,
      }
  )
  DENIED_FUNCTIONS = frozenset(
      {
          "load_extension",
          "readfile",
          "writefile",
          "edit",
          "fts3_tokenizer",
          "zipfile",
          "sqlar_compress",
          "sqlar_uncompress",
      }
  )
  ```

  Because the policy is an allowlist, every other action constant is denied
  without being enumerated — including `SQLITE_INSERT`, `SQLITE_UPDATE`,
  `SQLITE_DELETE`, `SQLITE_DROP_TABLE`, `SQLITE_ALTER_TABLE`,
  `SQLITE_CREATE_TABLE`, `SQLITE_CREATE_TEMP_TABLE`, `SQLITE_CREATE_VIEW`,
  `SQLITE_CREATE_INDEX`, `SQLITE_CREATE_TRIGGER`, `SQLITE_CREATE_VTABLE`,
  `SQLITE_DROP_VTABLE`, `SQLITE_PRAGMA`, `SQLITE_ATTACH`, `SQLITE_DETACH`,
  `SQLITE_TRANSACTION`, `SQLITE_SAVEPOINT`, `SQLITE_ANALYZE` and
  `SQLITE_REINDEX`. `SQLITE_RECURSIVE` is allowed so that recursive CTEs work;
  `SQLITE_FUNCTION` is allowed with a denylist so that `SUM`, `COUNT`,
  `strftime` and friends work while `load_extension` does not.
- **REQ-40 (MUST)** A denied action surfaces as an `sqlite3.Error` whose message
  contains `not authorized`. Do not call
  `conn.enable_load_extension(True)` anywhere.

### 3.9 Tool contracts

- **REQ-41 (MUST)** Exactly three tools are registered, no more, no fewer:
  `list_tables`, `describe_table`, `read_query`. Each is decorated with
  `@mcp.tool(structured_output=False)` and annotated `-> str`. Each returns a
  JSON document produced by

  ```python
  json.dumps(obj, ensure_ascii=False, allow_nan=False, separators=(",", ":"))
  ```

  Two helpers wrap it: `ok(payload: dict) -> str` emits `{"ok": true, **payload}`,
  `err(code, message, **extra) -> str` emits
  `{"ok": false, "error": {"code": ..., "message": ..., **extra}}`.
- **REQ-41a (MUST)** `server.py`'s import block is exactly these modules and no
  others:

  ```python
  from __future__ import annotations

  import json
  import logging
  import math
  import os
  import sqlite3
  import sys
  import time
  import urllib.parse
  from pathlib import Path
  from typing import Annotated, Any

  from mcp.server.mcpserver import MCPServer
  from pydantic import Field
  ```

  `Annotated` and `Field` are what give the two argument-taking tools their
  per-parameter JSON-Schema descriptions (REQ-45, REQ-46, verified by REQ-70).
  The order above is what `ruff` gate 2 requires (`mcp` sorts before `pydantic`
  in one third-party block); reordering it fails `I001`.
- **REQ-41b (MUST)** `server.py` ends with

  ```python
  if __name__ == "__main__":
      main()
  ```

  so that `python server.py` and `uv run --locked python server.py` both start
  the stdio transport.
- **REQ-42 (MUST)** No tool ever raises. Every failure path returns an error
  envelope. Error messages are single-sentence and truncated to 200 characters;
  no stack traces reach the client.
- **REQ-43 (MUST)** Error codes are exactly this closed set:

  | code | meaning |
  |---|---|
  | `policy_denied` | rejected by the read-only policy (lexical gate, authorizer, or multi-statement) |
  | `sql_error` | valid policy, invalid SQL (unknown table/column, syntax error) |
  | `timeout` | the 2 s query budget was exceeded |
  | `not_found` | `describe_table` was given a name that is not a queryable table |
  | `db_unavailable` | the database file is missing at call time |

  The body of `read_query` after the policy gate and connection setup is exactly:

  ```python
  # CONTRACT: sqlite3.Warning is NOT a subclass of sqlite3.Error, so it needs its
  # own clause; SQLite reports authorizer denials and multi-statement input as
  # sqlite3.Error subclasses distinguished only by message text.
  try:
      cur = conn.execute(sql)
      columns = [d[0] for d in cur.description] if cur.description else []
      fetched = cur.fetchmany(MAX_FETCH_ROWS)
      return ok(build_rows_envelope(columns, fetched))
  except sqlite3.Warning as exc:
      return err("policy_denied", str(exc)[:200])
  except sqlite3.Error as exc:
      text = str(exc)
      low = text.lower()
      if "interrupted" in low:
          return err("timeout", "Query exceeded the 2s budget.")
      if "not authorized" in low or "only execute one statement" in low:
          return err("policy_denied", f"Denied by the read-only policy: {text[:160]}")
      return err("sql_error", text[:200])
  finally:
      conn.close()
  ```

#### `list_tables`

- **REQ-44 (MUST)** Signature `def list_tables() -> str`. Docstring verbatim:


  Behaviour: enumerate with the query of REQ-33; for each name run

#### `describe_table`

- **REQ-45 (MUST)** Signature
  `def describe_table(table: Annotated[str, Field(description="Exact table name as returned by list_tables.")]) -> str`.
  Docstring verbatim:

  ```text
  Describe one table: its columns with types and nullability, primary key,
  foreign keys, row count and original CREATE TABLE statement.

  Use this after list_tables to learn a table's exact column names before
  writing SQL. The `table` argument must be an exact name from list_tables;
  unknown names, views and internal SQLite tables are rejected.

  Returns JSON:
    {"ok": true, "table": "orders", "description": "...", "row_count": 750,
     "columns": [{"name": "id", "type": "INTEGER", "not_null": true,
                  "default": null, "primary_key": true}, ...],
     "foreign_keys": [{"column": "customer_id", "references_table": "customers",
                       "references_column": "id"}, ...],
     "ddl": "CREATE TABLE orders (...)"}
  On an unknown name returns {"ok": false, "error": {"code": "not_found",
  "message": "...", "known_tables": [...]}}.
  ```

  Behaviour, in order:
  1. enumerate the queryable table set with the query of REQ-33;
  2. if `table` is not an exact member of that set, return
     `err("not_found", f"Unknown table '{table[:64]}'.", known_tables=<the set>)`
     — this is the identifier-injection defence, and it is why hostile names such
     as `orders"; DROP TABLE orders; --` never reach SQL;
  3. columns from
     `SELECT cid,name,type,"notnull",dflt_value,pk FROM pragma_table_info(?) ORDER BY cid`
     with `table` as a **bound parameter** — never string interpolation, and never
     a bare `PRAGMA` statement;
  4. foreign keys from
     `SELECT "from","table","to" FROM pragma_foreign_key_list(?) ORDER BY id`;
  5. DDL from `SELECT sql FROM sqlite_master WHERE type='table' AND name=?`;
  6. row count from `SELECT COUNT(*) FROM <quoted name>` where *quoted name* is
     `'"' + table.replace('"', '""') + '"'`.

  Name matching is case-sensitive and exact: `ORDERS` is `not_found`.

#### `read_query`

- **REQ-46 (MUST)** Signature

  Docstring verbatim:

  ```text
  Run one read-only SQL statement against the shop database and return the rows.

  Use this for every analytical question. Call list_tables and describe_table
  first if you do not already know the schema.

  Accepts exactly ONE statement, and only a SELECT or a WITH ... SELECT.
  Everything else is refused: INSERT, UPDATE, DELETE, DROP, ALTER, CREATE,
  REPLACE, PRAGMA, ATTACH, DETACH, VACUUM, EXPLAIN, transaction control and
  multiple statements separated by semicolons. The database is opened read-only,
  so no request can modify it.

  Limits: a query is cancelled after 2 seconds; at most 200 rows are returned;
  oversized text and binary values are truncated with a marker.

  Returns JSON:
    {"ok": true, "columns": ["name", "total"], "rows": [["Boots", 12], ...],
     "row_count": 2, "truncated": false, "truncation_reason": null,
     "cells_truncated": 0}
  `rows` is a list of positional arrays matching `columns`, so duplicate column
  names are preserved. NULL becomes null; binary values become
  "<blob:LENGTH:HEXPREFIX>". When `truncated` is true add LIMIT/ORDER BY or
  aggregate in SQL instead of paging.
  On failure returns {"ok": false, "error": {"code": "...", "message": "..."}}.
  ```

  Behaviour: `check_policy` → open restricted connection → `cur = conn.execute(sql)`
  → `columns = [d[0] for d in cur.description] if cur.description else []` →
  `fetched = cur.fetchmany(201)` → build the envelope per section 3.10.

### 3.10 Result values and size caps

- **REQ-47 (MUST)** Constants in `server.py`:

  ```python
  QUERY_BUDGET_SECONDS = 2.0
  PROGRESS_HANDLER_INSTRUCTIONS = 1000
  MAX_FETCH_ROWS = 201
  MAX_RETURN_ROWS = 200
  MAX_CELL_BYTES = 4096
  MAX_ENVELOPE_BYTES = 262144
  RESERVED_METADATA_BYTES = 4096
  BLOB_PREVIEW_BYTES = 64
  ```

- **REQ-48 (MUST)** `normalize_cell(value) -> tuple[Any, bool]` returns the
  JSON-safe value and whether it was truncated:

  | input | output |
  |---|---|
  | `None` | `None` (JSON `null`) |
  | `int` | the int unchanged |
  | finite `float` | the float unchanged |
  | non-finite `float` | the string `"NaN"`, `"Infinity"` or `"-Infinity"` |
  | `str` ≤ `MAX_CELL_BYTES` UTF-8 bytes | unchanged |
  | `str` longer | UTF-8 bytes cut to `MAX_CELL_BYTES - len("…[truncated]".encode())`, decoded with `errors="ignore"`, then `"…[truncated]"` appended; result is ≤ `MAX_CELL_BYTES` bytes; truncated flag true |
  | `bytes` | `f"<blob:{len(raw)}:{raw[:64].hex()}>"`; if longer than 64 bytes insert `…` before the closing `>` and set the truncated flag |

  Non-finite floats must be handled because the envelope is serialized with
  `allow_nan=False`, which would otherwise raise.
- **REQ-49 (MUST)** Row admission (`build_rows_envelope(columns, fetched)`):
  1. `row_limited = len(fetched) > MAX_RETURN_ROWS`; keep the first
     `MAX_RETURN_ROWS` rows as candidates;
  2. `budget = MAX_ENVELOPE_BYTES - RESERVED_METADATA_BYTES`; `used = 0`;
  3. for each candidate row: normalize every cell, counting truncations; compute
     `size = len(dumps(normalized_row).encode("utf-8")) + 1`; if
     `used + size > budget`, set `byte_limited = True` and **stop admitting rows**;
     otherwise `used += size` and append the row;
  4. `truncated = row_limited or byte_limited`;
     `truncation_reason` is `"byte_limit"` if `byte_limited`, else `"row_limit"` if
     `row_limited`, else `null`;
  5. the envelope is
     `{"columns", "rows", "row_count", "truncated", "truncation_reason", "cells_truncated"}`
     where `row_count == len(rows)`.

  This guarantees the serialized success envelope never exceeds
  `MAX_ENVELOPE_BYTES` UTF-8 bytes, and that the output is always valid JSON.
- **REQ-50 (MUST)** `columns` preserves duplicates and order exactly as SQLite
  reports them. `rows` are positional arrays, never objects. A zero-row result
  returns `"rows": []`, `"row_count": 0`, `"truncated": false`.
- **REQ-51 (MUST)** Result ordering is whatever SQLite returns; the server never
  re-sorts rows. Every test and documented query that depends on order carries an
  explicit `ORDER BY`.

## 8. Non-goals

- **NON-GOAL** More than three tools. No per-question tools, no `get_customer`,
  no `get_product_sales`. Three general tools cover every control question.
- **NON-GOAL** MCP resources, prompts, sampling, elicitation, completions,
  subscriptions or notifications. Tools only.
- **NON-GOAL** Any transport other than stdio. No HTTP, SSE, streamable-http,
  ports or sockets.
- **NON-GOAL** Write access of any kind: no migrations, no seeding, no
  regeneration of `data/shop.db`, no temp tables, no `ATTACH`.
- **NON-GOAL** Cursor-based or offset-based pagination. The contract is a hard
  200-row cap with a `truncated` flag; the agent narrows its SQL instead.
- **NON-GOAL** Connection pooling, caching, async database access or threading.
  One connection per tool invocation, closed in `finally`.
- **NON-GOAL** A SQL parser, query rewriter or query planner. The policy is the
  lexical gate plus the SQLite authorizer, nothing more.
- **NON-GOAL** Protection against a hostile local operator. `SHOP_DB_PATH` is
  trusted configuration; the server defends the database against the *agent's*
  queries, not against whoever launches the process.
- **NON-GOAL** Docker, CI workflows, packaging, publishing, `src/` layout,
  type-checking gates, coverage thresholds, structured logging or metrics.
- **NON-GOAL** Authentication, multi-tenancy, rate limiting beyond the 2 s query
  budget and the row/byte caps.
- **NON-GOAL** Localization. All code, docstrings, comments, README and log lines
  are English; only data values are Russian.
